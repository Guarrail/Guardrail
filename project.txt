GUARDRAIL
MVP Project Brief for UI/UX Designers & Developers
Project Name: GuardRail
Project Type: AI Agent Security / Programmable Capital Governance
Blockchain: Stellar
Development Stage: MVP — Sprint 1
Platform: Responsive Web Application + Policy Coordinator API
Environment: Stellar Testnet
MVP Scope: One AI Agent, One Controlled Wallet

1. Project Overview
GuardRail is a policy-controlled capital management infrastructure built on Stellar that allows AI agents to initiate financial transactions without giving them unrestricted control over digital assets.
The platform introduces a programmable security layer between an AI agent and the wallet it operates.
Instead of allowing an AI agent to transfer funds freely, GuardRail evaluates every proposed transaction against predefined financial policies before authorizing execution.
Operators can configure spending limits, approved recipients, supported assets, and human approval requirements.
The MVP will combine a policy evaluation service, cryptographically bound transaction permits, Stellar multisig controls, and an operator dashboard.
The goal is to allow AI agents to perform financial operations while ensuring that capital movements remain subject to enforceable policies and human oversight.
2. Problem Being Solved
AI agents are increasingly capable of initiating blockchain transactions, but traditional wallets are not designed to enforce detailed financial rules for autonomous software.
An AI agent with unrestricted signing authority can potentially:
Transfer more funds than intended.
Send funds to unauthorized addresses.
Exceed approved spending budgets.
Move unsupported or restricted assets.
Execute transactions without appropriate human review.
Make unintended transfers after receiving manipulated instructions.
GuardRail addresses these risks by separating transaction requests from final transaction authorization.
The agent can propose a transaction, but it cannot independently authorize the movement of funds from the protected wallet.

AI Agent Flow
AI agent submits a transaction request.
GuardRail validates the agent's identity.
GuardRail checks the request against configured policies.
GuardRail creates a permit for an eligible transaction.
The operator approves the transaction where required.
The authorized co-signer signs the exact approved transaction.
The transaction is submitted to Stellar.
GuardRail verifies the confirmed transaction.
The dashboard displays the result.

10. Module 1 — Policy & Permit Coordinator
Develop a backend service responsible for evaluating agent transaction requests.
Required Functionality
Receive authenticated agent requests.
Validate request format.
Identify controlled wallet.
Retrieve active policy.
Validate allowed asset.
Validate recipient address.
Check per-transaction amount limit.
Check daily spending limit.
Check weekly spending limit.
Determine approval requirements.
Reject non-compliant requests.
Generate transaction-bound permits.
Record policy decisions.
Initial Policy Rules
Rule 1: Maximum Transaction Amount
Reject requests above the configured per-transaction limit.
Rule 2: Spending Budget
Reject requests that would exceed the daily or weekly spending budget.
Rule 3: Recipient Allowlist
Only approved Stellar addresses can receive funds.
Rule 4: Asset Allowlist
Only explicitly permitted assets can be transferred.
Rule 5: Human Approval Threshold
Transactions above a configured threshold require explicit operator approval.
For the initial implementation, all executed payments should require a GuardRail-controlled co-signature, even when separate human approval is not required.
Permit Requirements
Each permit must contain:
Unique permit ID.
Agent ID.
Controlled wallet.
Recipient.
Asset.
Amount.
Transaction payload hash.
Policy version.
Creation time.
Expiration time.
Approval requirement.
Permit status.
A permit must be single-use and must not remain valid after cancellation, expiration, or policy invalidation.
11. Module 2 — Stellar Wallet Ownership & Multisig
Implement wallet ownership verification and controlled signing.
Required Functionality
Verify operator control of a Stellar wallet.
Register one dedicated controlled wallet.
Configure approved signer accounts.
Configure transaction thresholds.
Verify active signer configuration.
Prevent independent agent transfers.
Support controlled co-signing.
Record wallet configuration.
Recommended MVP Signing Model
Use a dedicated Stellar Testnet account with:
Agent signer: weight 1.
GuardRail co-signer: weight 1.
Medium transaction threshold: 2.
Operator master signer retained securely for recovery and administration.
Ordinary payment transactions should require the agent and GuardRail co-signer.
The GuardRail co-signer must only sign transactions that have passed policy checks and any required human approval.
Security Boundary: Stellar multisig enforces signer requirements, while the GuardRail coordinator enforces the detailed policies before contributing its signature.
The coordinator is therefore a security-critical component. Policy rules are not independently enforced by native Stellar multisig.
The development team must also validate operation thresholds, account-level authorization, signer changes, fee-bump behavior, and administrative permissions to prevent bypasses.

Important Requirements
A permit must not be reusable for another transaction.
The recipient and amount must not change after approval.
The coordinator must never sign a different payload from the approved one.
Expired permits must be rejected.

17. Security Requirements
GuardRail is a security-focused infrastructure project. The following requirements are mandatory:
Agent must not possess unrestricted wallet signing authority.
GuardRail co-signer key must remain separate from agent credentials.
Private keys must never be exposed through frontend or API responses.
Every transaction must pass policy evaluation.
Human approval must be enforced where required.
Permits must be transaction-bound and single-use.
Duplicate requests must not bypass controls.
Concurrent requests must not exceed spending limits.
Recipient and asset allowlists must be enforced.
Signing services must revalidate transaction details.
Administrative wallet operations must not bypass the intended signing configuration.
Emergency agent disabling must prevent new co-signatures.
All testing must use Stellar Testnet assets.

22. Definition of Done
GuardRail MVP is complete when one authenticated AI agent can request a Stellar payment from one controlled Testnet wallet, and that payment can execute only after satisfying the configured policy and required signing conditions.
The demonstration must show both successful and blocked transactions.
The agent must be unable to independently move funds without the GuardRail co-signer.
The operator must be able to review transaction details, approve or reject requests requiring human oversight, and verify executed transactions through Stellar.

Final Team Instruction: GuardRail must demonstrate enforceable financial controls, not merely a dashboard that displays AI agent transaction requests.
The most important deliverable is a working security boundary in which the agent cannot independently transfer protected funds and the GuardRail co-signer refuses transactions that violate the active policy.
The first sprint should prioritize one secure, fully tested agent-to-wallet transaction flow before expanding to multiple agents, complex policies, or enterprise features.
